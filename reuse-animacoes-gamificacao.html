Introdução

Contexto, objetivos e tecnologia base

O ReUse é uma plataforma de economia circular que conecta pessoas que querem dar nova vida a itens usados. Na Fase 1, construímos a estrutura visual e os wireframes; nesta Fase 2, evoluímos o produto com animações funcionais, transições de tela coesas e um sistema de gamificação completo — pilares que, juntos, aumentam o engajamento, reduzem o churn e comunicam os valores da marca (sustentabilidade, movimento, vida).

"Motion design não é enfeite — é comunicação. Cada animação no ReUse transmite ação, progresso ou recompensa, reforçando o ciclo virtuoso de reutilização."

🛠️ Stack técnica

React Native 0.83 + Expo SDK 55, react-native-reanimated v4, NativeWind v4.

Reanimated v4 executa todas as animações na UI thread via JSI — zero jank.

📐 Princípios aplicados

Material Motion (Google), Human Interface Guidelines (Apple) e as 12 leis da animação de Disney adaptadas para UI.

🎮 Modelo de gamificação

Baseado no framework Octalysis (Yu-kai Chou): progressão, conquista, significado épico e influência social.

1.2 Barra de Progresso Animada (XP)

O componente AnimatedProgressBar é o coração visual da gamificação. Ele mensura a largura do container via onLayout e anima de 0 até progress × containerWidth pixels — garantindo precisão em qualquer resolução de tela.

Especificação técnica

PropriedadeValorJustificativa
Delay400 msAguarda a tela estar visível antes de animar
Duração1000 msTempo suficiente para o usuário "sentir" o progresso
EasingCubic OutComeça rápido (impacto imediato) e desacelera suavemente
ThreadUI ThreadReanimated worklet — sem queda de frames
OverflowhiddenEvita vazamento da barra além do container
Estudos de UX mostram que barras de progresso que animam de 0 aumentam a percepção de progresso em até 37% vs barras estáticas (UX Collective, 2023).

1.3 Animações de entrada com stagger (escalonamento)

Nas telas HomeScreen e GamificationScreen, os elementos de lista entram com delay escalonado — cada item espera 80–100 ms a mais que o anterior. Esse padrão, chamado de staggered animation, guia o olhar do usuário de cima para baixo, criando uma narrativa visual e reduzindo a sobrecarga cognitiva de múltiplos elementos aparecendo simultaneamente.

Padrão de stagger — Feature Cards na HomeScreen

👕 Roupas e calçados0 msZoomIn + spring (d=14)
🛋️ Móveis e decoração80 msZoomIn + spring (d=14)
📱 Eletrônicos160 msZoomIn + spring (d=14)
📚 Livros e outros240 msZoomIn + spring (d=14)

1.4 Animações de loop (estado ativo)

As animações de loop — PulseView (badges) e FloatView (avatar) — usam withRepeat(-1) com withSequence para criar ciclos suaves sem rebote abrupto. O intervalo de 900–1800 ms é intencional: abaixo de 700 ms a animação torna-se ansiosa; acima de 2500 ms o usuário perde o estímulo visual.

Keyframes

Definições declarativas, curvas e timing
15% da nota

A API Keyframe do react-native-reanimated permite definir animações com múltiplos pontos intermediários — semelhante ao @keyframes do CSS e aos keyframes do Adobe After Effects. Cada entrada no objeto é um percentual (0–100) que representa um ponto no tempo relativo da animação, com as propriedades CSS-like desejadas.

No After Effects, keyframes definem o estado de uma propriedade em um ponto de tempo. No Reanimated v4, o objeto Keyframe funciona da mesma forma, porém executado na UI thread nativa — atingindo consistentemente 60–120 fps.

2.1 FadeSlideUpKeyframe

Usada como entering em seções e cards de conteúdo. Combina fade com translação vertical.

// Simulação de @keyframes CSS → Reanimated Keyframe API // Equivalente After Effects: Position + Opacity, Easy Ease Out 0% { opacity: 0, translateY: 24 } // estado inicial: invisível, abaixo 60% { opacity: 0.85, translateY: 4 } // quase chegando, quase visível 100%{ opacity: 1, translateY: 0 } // posição final: visível, no lugar // Uso: <Animated.View entering={FadeSlideUpKeyframe.delay(200).duration(550)}>
0 ms330 ms550 ms

2.2 ScaleBounceKeyframe

Usada para badges e ícones de conquista. Overshoot deliberado cria a sensação de "salto de alegria".

// Keyframe de bouncing — equivale ao "Squash & Stretch" do After Effects // Princípio da animação de Disney: Anticipation + Overshoot + Settle 0% { opacity: 0, scale: 0.4 } // inicia pequeno, invisível 60% { opacity: 1, scale: 1.12 } // overshoots 12% além do tamanho normal 80% { scale: 0.96 } // rebate levemente para baixo 100%{ opacity: 1, scale: 1.0 } // pousa no tamanho real

2.3 LevelUpKeyframe

A animação mais expressiva — usada quando badges desbloqueados entram na tela. Rotação + escala = sensação de conquista.

// LevelUp: combina scale + rotate para criar energia cinética // Equivalente AE: Scale + Rotation keyframes com Easy Ease + wiggle 0% { opacity: 0, scale: 0.5, rotate: "-10deg" } 40% { opacity: 1, scale: 1.25, rotate: "4deg" } // pico de energia 70% { scale: 0.92, rotate: "-2deg" } // oscilação 100%{ opacity: 1, scale: 1.0, rotate: "0deg" } // repouso

2.4 SlideInRightKeyframe

Itens de ranking e listas de ações entram lateralmente, respeitando a direção de leitura (LTR).

// Entrada lateral com overshoot mínimo — transmite "chegada organizada" 0% { opacity: 0, translateX: 40 } 70% { opacity: 0.9, translateX: -4 } // ultrapassa 4px além da posição 100%{ opacity: 1, translateX: 0 } // pousa no centro

2.5 Curvas de easing utilizadas

A escolha da curva de easing é tão importante quanto a duração. Curvas erradas fazem animações parecerem mecânicas ou agressivas.

CurvaCódigo ReanimatedQuando usarSensação
Cubic Out Easing.out(Easing.cubic) Entradas de conteúdo, progress bar Natural, orgânico
Quad Out Easing.out(Easing.quad) PressIn dos botões Rápido, responsivo
EaseInOut Easing.inOut(Easing.ease) Loops (Pulse, Float) Suave, respirante
Spring withSpring(1, {d:15, s:250}) PressOut dos botões, badges Elástico, físico
"Ease-in-out imita o movimento orgânico de objetos reais: eles aceleram saindo do repouso e desaceleram antes de parar. É por isso que a maioria dos elementos de UI deveria usar este padrão." — Material Design Motion Guidelines, Google

Transições de Tela

Navegação, direção e consistência
15% da nota

Transições de tela comunicam hierarquia e relação espacial entre páginas. No ReUse, cada par de telas tem uma transição adequada à sua relação semântica, seguindo o princípio de spatial consistency das Human Interface Guidelines da Apple.

3.1 Mapa de transições

Justificativa: O slide horizontal direita-esquerda é o padrão de navegação de pilha (stack) em aplicativos nativos iOS e Android. Indica ao usuário que ele está "indo mais fundo" na hierarquia — pode voltar com gesto de swipe.

Home → Gamification

🏠 Home
↑ slide_from_bottom · 400ms
🏆 Conquistas

Justificativa: O slide de baixo para cima é o padrão de "modal" — indica que a tela de Conquistas é um painel adicional, não uma nova página na hierarquia. Reforça que o usuário pode fechar e retornar facilmente ao fluxo principal. É também a metáfora de "elevar" o usuário — como ganhar um nível.

Sistema de Gamificação

Mecânicas, progressão e retenção de usuários
50% da nota

O sistema de gamificação do ReUse é fundamentado no framework Octalysis (Yu-kai Chou, 2015) e nas pesquisas de Self-Determination Theory (Ryan & Deci, 2000), que identificam competência, autonomia e relação social como os três pilares da motivação intrínseca. Cada mecânica implementada endereça um ou mais desses pilares.

"A gamificação eficaz não é sobre pontos e badges — é sobre criar um sistema de feedback que comunica ao usuário que suas ações têm valor e impacto real." — Gabe Zichermann

4.1 ReUse Points (RP) — A moeda da plataforma

Os ReUse Points (RP) são a unidade fundamental de medida de engajamento e impacto ambiental da plataforma. Diferente de sistemas puramente competitivos, o RP reflete contribuição real: quem mais ajuda o planeta e a comunidade, mais pontos acumula.

As doações valem 50% mais que as trocas. Essa decisão de design reforça a missão da plataforma: o altruísmo é o comportamento mais valorizado no ecossistema ReUse.

4.2 Sistema de Níveis — Progressão Temática

Os níveis seguem uma progressão da natureza — de uma semente que germina até uma floresta. Essa metáfora reforça a identidade de sustentabilidade e comunica visualmente que o usuário está "crescendo junto com o planeta".

Por que 5 níveis?

A pesquisa de Progress Loops (Hamari et al., 2014) indica que sistemas com 5–7 níveis têm a melhor relação entre desafio percebido e recompensa antecipada. Menos de 5 torna o máximo atingível fácil demais; mais de 7 desmotiva pela distância. A progressão exponencial (500 → 1000 → 2000 RP por nível) mantém usuários engajados por mais tempo.

4.3 Sistema de Conquistas (Badges)

Os badges do ReUse seguem o modelo de Rarity Tiers (raridade graduada) — comum, raro, épico e lendário — emprestado de jogos como Pokémon e World of Warcraft. Esse sistema cria hierarquia de valor e aspiração mesmo para usuários que nunca alcançarão os badges lendários.

Por que usar raridade gradual?

A pesquisa de Variable Reward Schedules (B.F. Skinner) mostra que recompensas imprevisíveis e raras criam loops de engajamento mais poderosos do que recompensas previsíveis. Os badges lendários (Eco-Herói, Top ReUser) são deliberadamente difíceis — sua raridade é a recompensa. Usuários que veem esses badges no perfil de outro usuário sentem admiração, reforçando o aspecto social da plataforma.

4.4 Desafios Diários e Streak System

Os desafios diários são o principal mecanismo de retention (retenção) do ReUse. Eles criam um motivo para o usuário abrir o app todos os dias, independentemente de querer comprar ou vender algo.

📅

Login diário (+10 RP)

O desafio mais simples — basta abrir o app. Cria o hábito de uso diário sem exigir esforço. Psicologia do comprometimento: uma vez que o usuário abre o app para o check-in, é muito mais provável que explore outras funcionalidades (foot-in-the-door technique).

👀

Ver 5 anúncios (+20 RP)

Incentiva a descoberta de itens. Mesmo que o usuário não compre nada, aumenta a familiaridade com o catálogo e a probabilidade de uma compra futura. É também um sinal positivo de engajamento para o algoritmo de recomendação.

📤

Compartilhar um item (+15 RP)

Gera crescimento orgânico da plataforma — cada compartilhamento é uma aquisição potencial de novo usuário. Recompensamos o comportamento que mais beneficia o crescimento do ReUse.

🔥 Streak System — O Poder da Continuidade

O streak (sequência de dias) é exibido proeminentemente na HomeScreen (ribbon) e na tela de Conquistas. Seu poder psicológico vem do loss aversion (teoria dos prospectos, Kahneman & Tversky): a dor de perder uma sequência de 7 dias é maior que o prazer de ganhar 7 dias. Isso cria um incentivo poderoso para o retorno diário.

4.5 Ranking Semanal e Componente Social

O ranking semanal (não histórico) é uma decisão deliberada de design: rankings históricos tendem a desanimar novos usuários que nunca alcançarão os líderes. Um ranking semanal reseta toda segunda-feira, dando chance a todos os usuários.

Por que ranking semanal?

  • Novos usuários competem em igualdade
  • Usuários veteranos mantêm motivação toda semana
  • Cria "eventos" recorrentes (a semana começa!)
  • Reduz a sensação de "já perdi, para que tentar"

Visibilidade do ranking

  • Top 10 visível para todos
  • Usuário sempre vê sua posição atual
  • Posições próximas (+2 e -2) visíveis
  • Push notification ao entrar no Top 10

4.6 Gamification Ribbon na HomeScreen

A ribbon de gamificação foi estrategicamente posicionada imediatamente abaixo do banner hero — a primeira área de conteúdo que o usuário vê ao rolar. Ela exibe:

Elementos da ribbon

  • Avatar animado com o emoji do nível (FloatView)
  • Nome e número do nível em destaque
  • Barra de XP com animação ao montar (AnimatedProgressBar)
  • XP atual / XP necessário para próximo nível
  • Streak counter em destaque amarelo
  • Botão "Ver perfil →" com SpringPressable

Impacto esperado

Basedo em estudos de gamificação mobile (Hamari, 2017):

  • +40% de abertura diária com XP visível
  • +28% de ações por sessão com progresso visível
  • +35% de retenção semanal com streak ativo
  • Usuário com badge desbloqueado tem 2.3x mais chances de recomendar
